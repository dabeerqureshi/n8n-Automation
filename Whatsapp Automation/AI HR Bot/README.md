# AI WhatsApp HR Recruitment Bot (MVP)

A local, self-hosted recruitment assistant built with **n8n**, **Ollama**, and the **WhatsApp Cloud API**. Candidates can browse jobs, ask HR/FAQ questions, and get the official apply link — all over WhatsApp.

## Files in this package

| File | Purpose |
|---|---|
| `whatsapp-hr-bot.json` | Importable n8n workflow |
| `jobs.csv` | Sample job listings data |
| `faqs.csv` | Sample HR FAQ data |
| `README.md` | This guide |

## Prerequisites

- n8n running locally (self-hosted, v1.60+ recommended) — Docker or `npm i n8n -g`
- [Ollama](https://ollama.com) installed and running locally, with a model pulled, e.g.:
  ```bash
  ollama pull llama3.1
  ```
- A Meta developer account with a WhatsApp Business app (Cloud API), a phone number ID, and a permanent access token
- A public HTTPS URL pointing at your n8n instance so Meta can reach your webhook (use `ngrok`, Cloudflare Tunnel, or a reverse proxy with a real domain in production)

## 1. Import the workflow

1. Open n8n → **Workflows** → **Import from File** → select `whatsapp-hr-bot.json`.
2. The workflow has 26 nodes across 4 branches: **Job Discovery**, **Apply for Job**, **FAQ**, and **Fallback/Greeting**.

## 2. Place the data files

By default the workflow reads CSVs from `/data/jobs.csv` and `/data/faqs.csv` inside the n8n container/host.

- Copy `jobs.csv` and `faqs.csv` into that folder, **or**
- Set the environment variables below to point anywhere you like.

If you're running n8n in Docker, mount a volume, e.g.:
```bash
docker run -it --rm \
  -p 5678:5678 \
  -v ~/.n8n:/home/node/.n8n \
  -v $(pwd)/data:/data \
  n8nio/n8n
```

## 3. Set environment variables

Set these in n8n (Settings → Environment Variables, or your `.env` / Docker `-e` flags):

| Variable | Description | Example |
|---|---|---|
| `WHATSAPP_VERIFY_TOKEN` | Any string you choose; must match the token you enter in the Meta App dashboard | `my-secret-verify-token` |
| `WHATSAPP_PHONE_NUMBER_ID` | From Meta App → WhatsApp → API Setup | `109876543210123` |
| `OLLAMA_BASE_URL` | Where Ollama is reachable from n8n | `http://localhost:11434` |
| `OLLAMA_MODEL` | Model to use for intent detection | `llama3.1` |
| `JOBS_CSV_PATH` | Path to jobs CSV | `/data/jobs.csv` |
| `FAQS_CSV_PATH` | Path to FAQs CSV | `/data/faqs.csv` |

> Note: if n8n runs in Docker and Ollama runs on your host machine, use `http://host.docker.internal:11434` instead of `localhost`.

## 4. Add the WhatsApp credential

The **Send WhatsApp Reply** node uses an HTTP Header Auth credential:

1. In n8n, create a new credential: **HTTP Header Auth**.
2. Name it `WhatsApp Cloud API`.
3. Header name: `Authorization`
4. Header value: `Bearer YOUR_PERMANENT_ACCESS_TOKEN`
5. Assign this credential to the **Send WhatsApp Reply** node.

## 5. Configure the Meta webhook

1. Activate the workflow in n8n (toggle in the top right).
2. Copy the **production** webhook URL from the **Webhook - Verify** node, e.g.
   `https://your-domain.com/webhook/whatsapp-webhook`
3. In Meta App Dashboard → WhatsApp → Configuration:
   - **Callback URL**: the URL above
   - **Verify Token**: same value as `WHATSAPP_VERIFY_TOKEN`
   - Subscribe to the `messages` webhook field
4. Meta will send a GET request to verify — the **Webhook - Verify** branch handles this automatically and returns the challenge.

## 6. Test it

Send a WhatsApp message to your business number:

- `"I'm looking for AI Engineer jobs"` → Job Discovery branch
- `"What are your office timings?"` → FAQ branch
- `"I want to apply for Backend Developer"` → Apply branch
- `"hi"` → Fallback/greeting

Watch the n8n **Executions** tab to debug each node's output.

## How it works

```
Meta WhatsApp
      │
      ▼
Webhook - Receive Message  (instant 200 ack, so WhatsApp never times out)
      │
      ▼
Extract Message  →  IF Has Text Message?  → No  → No-Op (ignore delivery/read receipts)
      │ Yes
      ▼
Ollama - Detect Intent  (local LLM classifies: job_discovery / apply_job / faq / greeting / other)
      │
      ▼
Parse Intent  (safe JSON parsing with fallback to "other")
      │
      ▼
Switch - Route Intent
   ├── job_discovery → Read jobs.csv → keyword-score → format list
   ├── apply_job      → Read jobs.csv → match title  → apply link or "closed"
   ├── faq             → Read faqs.csv → keyword-match → answer
   └── other/greeting → static help message
      │
      ▼
Send WhatsApp Reply  (Graph API)
```

### Why keyword matching instead of asking the LLM to answer directly?

Job and FAQ answers are matched **deterministically** against the CSV data (word-overlap scoring) rather than generated by the LLM. This guarantees the bot never invents a job, salary, or policy that doesn't exist — Ollama is only used for **intent classification**, not for generating factual answers. This matches the "never invent jobs, salaries, benefits, or policies" requirement from the original spec.

## Updating job listings / FAQs

Just edit `jobs.csv` / `faqs.csv` directly — no redeploy needed, the workflow reads the file fresh on every message. Keep the header row exactly as-is:

**jobs.csv columns**: `Job ID, Position, Department, Location, Experience, Salary, Skills, Status, Apply URL`
(Status must be exactly `Open` or `Closed`.)

**faqs.csv columns**: `Question, Answer`

## Production checklist

- [ ] Use a real HTTPS domain (not a temporary ngrok URL) behind a reverse proxy
- [ ] Rotate the WhatsApp access token to a **permanent** System User token (not the 24-hour temporary one)
- [ ] Restrict n8n's editor UI with authentication (n8n basic auth or SSO)
- [ ] Move CSVs to a database (e.g. Postgres or Google Sheets) once you outgrow file-based storage — the CSV nodes can be swapped for Google Sheets nodes with the same downstream logic
- [ ] Add a **Simple Memory** / session node keyed by the sender's phone number if you want multi-turn conversation context
- [ ] Add logging/error-workflow in n8n (Settings → Error Workflow) so failures alert you
- [ ] Set the Ollama request timeout and add a fallback message if Ollama is unreachable (currently 30s timeout on the intent node — adjust if using a larger/slower model)
- [ ] Rate-limit or debounce rapid repeat messages from the same number if needed

## Extending

- **Human handoff**: add a branch that forwards to a real recruiter if the FAQ match score is 0 for multiple messages in a row.
- **Resume collection**: add a node to receive WhatsApp document/media messages and store them (currently the bot sends the external apply link instead of collecting resumes directly).
- **Multi-language**: extend the intent-detection system prompt to also detect language and localize replies.
